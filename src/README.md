# Расчёт состава плазмы Xe и Cs

Python-программа по семинарской схеме: линеаризация уравнений по логарифмам концентраций, решение линейной системы методом Гаусса/LU, отдельное половинное деление для параметра неидеальности Γ. При линеаризации коэффициенты и поправки фиксируются; при проверке пробного состава пересчитываются заново.

**Версия 0.3.0 поддерживает три вида прогонки:** Tₑ=Tₕ=T, изменение Tₑ/Tₕ при фиксированной Tₕ, рост Tₕ при фиксированном Tₑ/Tₕ. Xe и Cs считаются отдельно. При разных температурах применяется идеальное приближение. Энергия и транспорт относятся к следующему этапу. Набор связанных уровней фиксирован и не меняется из-за ΔI в ходе решения.

## Быстрый запуск

Требуются `uv` и Python 3.10 или новее. Из папки, где лежат `main.py` и `pyproject.toml`:

```bash
uv sync --locked
uv run main.py --validate-only
uv run main.py
```

Приложенные пользователем 12 исходных NIST CSV уже находятся в `input`, без изменений содержимого. Перед расчётом можно проверить отчёт `results/data_validation.json`. Файл `uv.lock` фиксирует версии зависимостей; `uv sync --locked` создаёт окружение `.venv`. Активировать его вручную при запуске через `uv run` не требуется.

Если ты самостоятельно меняешь зависимости в `pyproject.toml`, выполни `uv sync` без `--locked`, чтобы обновить `uv.lock`.

Команды для отдельного режима:

```bash
uv run main.py --element Xe --model ideal
uv run main.py --element Cs --model nonideal
uv run main.py --max-charge 4 --output-dir results_z4
```

Пути можно переопределить аргументами `--input-dir` и `--output-dir`. `--quiet` отключает промежуточную печать, но сохраняет файлы. Также доступна команда `uv run plasma-xe-cs` с теми же аргументами. Начальные физические параметры редактируются в `config.py`.

## Рост температуры при фиксированном gamma

В этом режиме фиксируются **давление p и отношение gamma=Tₑ/Tₕ**, а температура тяжёлых частиц Tₕ растёт по прежней температурной сетке. Для каждой точки Tₑ=gamma·Tₕ. Например, при gamma=2:

| Tₕ, K | Tₑ, K | gamma |
|---:|---:|---:|
| 3000 | 6000 | 2 |
| 4000 | 8000 | 2 |
| 5000 | 10000 | 2 |

Запуск:

```bash
uv run main.py --fixed-gamma 1
uv run main.py --fixed-gamma 2
uv run main.py --fixed-gamma 3 --temperature-start-k 3000 --temperature-stop-k 10000 --temperature-step-k 250
```

Начало, конец и шаг задают **Tₕ**, поэтому верхняя электронная температура равна `gamma * temperature_stop_k`. Если границы не переданы в командной строке, используются значения из `config.py`: Tₕ=3000–30000 K с шагом 250 K. Давление также берётся из конфигурации или `--pressure-pa`.

`--fixed-gamma 1` воспроизводит прежние однотемпературные концентрации. При gamma=1 доступны оба режима `ideal` и `nonideal` из настроек; конкретный режим можно выбрать через `--model`. При gamma≠1 команда выбирает `ideal`, а явное сочетание с `--model nonideal` выдаёт ошибку: двухтемпературные неидеальные поправки пока не заданы.

Каждый запуск сохраняет результаты отдельно: например, `results_fixed_gamma_1` и `results_fixed_gamma_2`. Явный `--output-dir` задаёт другую папку. В таблицах есть Tₕ, Tₑ и постоянное `gamma_Te_Th`. На графиках по горизонтали отложена **Tₕ**, в заголовке указаны **gamma и p**. Пример имени общего графика — `Xe_ideal_fixed_gamma_2.png`. Четыре группы графиков также сохраняются.

Для постоянного выбора режима в `config.py`:

```python
sweep_mode="fixed_ratio",
fixed_temperature_ratio=2.0,
models=("ideal",),
output_dir=BASE_DIR / "results_fixed_gamma_2",
```

В этом режиме `heavy_temperature_k` и `temperature_ratios` не используются: они относятся к другой прогонке, где Tₕ постоянна. Если дополнительная промежуточная точка нужна для сходимости, обе температуры изменяются пропорционально, сохраняя заданное отношение.

| Режим | Фиксируем | Меняем | Запуск |
|---|---|---|---|
| Однотемпературный | p, gamma=1 | Tₕ=Tₑ=T | `uv run main.py` |
| По отношению температур | p, Tₕ | gamma, Tₑ=gamma·Tₕ | `uv run main.py --two-temperature` |
| При постоянном отношении | p, gamma | Tₕ, Tₑ=gamma·Tₕ | `uv run main.py --fixed-gamma 2` |

## Изменение gamma при фиксированной Tₕ

Запуск нового режима с настройками из `config.py`:

```bash
uv run main.py --two-temperature
```

При текущих настройках фиксируются **p=100000 Па и Tₕ=4000 K**. Отношение **gamma=Tₑ/Tₕ** изменяется от 1 до 5 с шагом 0.25, поэтому Tₑ изменяется от 4000 до 20000 K. Считаются оба элемента и все заряды до +4, сохраняются четыре группы графиков и общий график каждого элемента. В этом режиме применяется только идеальная модель.

Параметры можно переопределить в командной строке:

```bash
uv run main.py --two-temperature --element Xe --heavy-temperature-k 4000 --pressure-pa 100000 --temperature-ratios 1 1.25 1.5 2 3 4 5
uv run main.py --two-temperature --output-dir results_gamma --quiet
uv run main.py --two-temperature --validate-only
```

Сетка должна содержать положительные конечные числа в возрастающем порядке без повторений. **Контрольная точка gamma=1 добавляется автоматически**, если её нет в списке. Возможны также значения gamma<1. Базовое решение при Tₑ=Tₕ вычисляется первым, а для следующих точек применяется протяжка. При сбое добавляются промежуточные значения Tₑ, при этом Tₕ и p остаются фиксированными.

При запуске с `--two-temperature` результаты по умолчанию сохраняются в `results_two_temperature`, то есть отдельно от прежнего `results`. Для другого исходного `output_dir` добавляется суффикс `_two_temperature`; явный `--output-dir` задаёт папку напрямую.

В `config.py` можно изменить:

```python
heavy_temperature_k=4000.0,
temperature_ratios=tuple(1.0 + 0.25 * i for i in range(17)),
```

Чтобы новый режим запускался без флага, задай `sweep_mode="temperature_ratio"`, `models=("ideal",)` и отдельную папку `output_dir=BASE_DIR / "results_two_temperature"`. По умолчанию `sweep_mode="temperature"` сохраняет обычный однотемпературный запуск.

В CSV и печатной таблице есть `T_h_K`, `T_e_K` и **`gamma_Te_Th`**. Старый столбец `T_K` оставлен как другое имя для Tₕ. **`gamma_Te_Th` и `Gamma` — разные величины**: первый столбец содержит заданное отношение температур, второй — параметр неидеальной поправки. В идеальном режиме `Gamma=alpha=deltaI_max_eV=0` означает, что эти поправки выключены; отдельная оценка физической неидеальности не выполняется.

По горизонтали новых графиков отложено Tₑ/Tₕ, в заголовке указаны фиксированные Tₕ и p. Например, общий график называется `Xe_ideal_two_temperature.png`, первая группа — `Xe_ideal_two_temperature_group1_neutral_ion1_e.png`. Концентрации ниже 10^16 м^-3 обрезаются только на изображении, как в присланной версии; в CSV сохраняются все вычисленные значения. Если вся группа лежит ниже порога, это отмечается на графике.

Обе температуры задаются извне. Это расчёт состава для заданных условий, а не эволюции температур во времени. Электронные уровни и ионизационные соотношения описываются при Tₑ; температуры поступательного движения атомов и ионов равны Tₕ. Это выбранное двухтемпературное приближение. **Режим nonideal при Tₑ≠Tₕ пока не реализован**: для него требуется отдельно задать модель поправок. Комбинация `--two-temperature --model nonideal` выдаёт понятную ошибку.

## Входные файлы

Файлы уровней: `input/energy_levels/xe_1.csv` ... `xe_5.csv` и аналогично `cs_1.csv` ... `cs_5.csv`. **Суффикс 1 — нейтрал (заряд 0), суффикс 2 — заряд +1.** При максимальном заряде +1 нужны только первые два файла каждого элемента.

Пороги: `input/ionization_energies/xe.csv` и `cs.csv`. Нужна полная таблица ионизации, включая порог последнего учитываемого иона: он используется для отбора его связанных уровней. Например, для состава 0,+1 нужны пороги 0→+1 и +1→+2, хотя второй порог не входит в уравнение перехода внутри состава.

Поддерживается исходная выгрузка NIST CSV/Tab-delimited, в том числе текстовые обёртки `="..."`, разделённые `Prefix/Level/Suffix`, дробные J. Можно использовать нормализованные CSV:

```csv
energy_eV,J
```

или

```csv
energy_eV,g
```

Здесь `g` — статистический вес 2J+1, а не фактор Landé. Заголовки NIST `Level (eV)`, `Level (cm-1)`, `J`, `Configuration`, `Term` распознаются непосредственно. Нормализованная таблица порогов:

```csv
charge,ionization_energy_eV,uncertainty_eV
```

Вместо этих названий поддерживаются NIST `Ion Charge`, `Ionization Energy (eV)`, `El. Name`/`Element name`, `Sp. Name`/`Spectrum name`. Заряд при наличии только спектра или пустой ячейки заряда восстанавливается из обозначений Xe I, Xe II и т.д. Если указаны и спектр, и заряд, проверяется их согласованность; элемент также проверяется. Пустой последний столбец NIST не мешает чтению.

Единицы энергии читаются из заголовка; поддерживаются eV, cm^-1, Rydberg, Hartree, GHz. Если единицы отсутствуют, применяется **явная настройка** `default_energy_unit` и выводится предупреждение. Перед расчётом её нужно проверить. Внутри программы энергии выражены в эВ, температуры — K, давление — Па, физические концентрации — м^-3.

### Что делает проверка данных

- Требует основной уровень с энергией 0 и положительные статистические веса.
- Исключает строки Limit, отсутствующие/неоднозначные энергии и J, автоионизационные строки с соответствующим маркером.
- При `bound_levels_only=True` исключает уровни с энергией не ниже исходного порога. Это фиксированный набор; понижение порога не меняет его в данной версии.
- Перечисление J через запятую трактует как неразрешённые уровни с суммарной кратностью; альтернативы через `or` исключает и отражает в отчёте.
- Сохраняет число исключений и до трёх примеров каждой причины: исходные ячейки и номера строк CSV. Пропуски не заменяются нулями.
- Считает принятые энергии с квадратными/круглыми скобками в `estimated_rows`. Численное значение используется без скобок; число таких строк сохраняется в отчёте.
- Сообщает о точных повторах строк, но не объединяет уровни только по равенству энергии.
- При нехватке обязательного файла/основного уровня/порога прекращает расчёт с понятным сообщением.

Мало уровней или исключённые неопределённые строки могут существенно влиять на статистические суммы. Успех численного решателя не означает полноту атомных данных.

Для включённых CSV при `max_charge=4` принимается следующее число уровней:

| Элемент | Нейтрал | +1 | +2 | +3 | +4 |
|---|---:|---:|---:|---:|---:|
| Xe | 342 | 161 | 157 | 94 | 53 |
| Cs | 174 | 303 | 173 | 115 | 49 |

В частности, в `xe_1.csv` исключаются две строки `Limit` и 101 уровень с энергией не ниже первого порога ионизации. Это следствие настройки `bound_levels_only=True`, а не ошибка CSV. В `cs_1.csv` выше порога исключаются четыре уровня. Фильтр сравнивает энергии с исходным порогом; изменение статистических сумм из-за ΔI пока не моделируется.

## Формулы и численный метод

Используется масштаб n_ref = 10^24 м^-3 = 10^18 см^-3. Неизвестные — y=(v,x₀,...,x_Z), где aₑ=exp(v), a_z=exp(x_z), n=a·n_ref.

В `model.py` по физическим константам вычисляются коэффициенты листочка: A* ≈ 2.414683e-3, CΓ ≈ 5.863360e10, Cα ≈ 2.842511e-12. Давление нормируется как B=p/(k_BT n_ref), поэтому неоднозначная подпись «атм» с фотографии не используется.

Уравнения: v+x_(z+1)-x_z=ln(K_z*), aₑ=Σza_z, aₑ+Σa_z−α=B. В идеальном режиме Γ=α=ΔI=0. В неидеальном Γ находится половинным делением на доказанном интервале [0,Γ_D], затем вычисляются α и ΔI. При поиске Γ используется нормированная неизвестная q=Γ/Γ_D, что позволяет задавать точность независимо от малого значения самого Γ.

Система для новых логарифмов собирается напрямую, с замороженными поправками. В `np.linalg.solve` используется LU с выбором главного элемента — библиотечная реализация исключения Гаусса. Если полный шаг ухудшает ошибки исходных уравнений, он уменьшается. Начальное приближение получается аналитически для нейтрала и однократного иона; старшие состояния добавляются по логарифмической рекурсии Саха.

Успех принимается по выполнению ионизационных соотношений, относительному балансу заряда и давления и точности Γ. Малый шаг не используется вместо проверки уравнений. При несходимости сохраняется статус `failed`; пробные концентрации не выдаются за результат.

Alpha — поправка давления. Коэффициент уменьшения численного шага внутри решателя называется eta.

### Уравнения идеального двухтемпературного режима

При фиксированных p,Tₕ и заданном gamma используется Tₑ=gamma·Tₕ. Все U_z и K_z* вычисляются при Tₑ:

```math
U_z(T_e)=\sum_\ell g_{z\ell}\exp\!\left(-\frac{E_{z\ell}}{k_BT_e}\right),\qquad
K_z^*=2A^*T_e^{3/2}\frac{U_{z+1}(T_e)}{U_z(T_e)}
\exp\!\left(-\frac{I_z}{k_BT_e}\right).
```

Здесь g=2J+1, E — энергия возбуждения от основного уровня того же иона, I_z — порог перехода z→z+1, K_z*=K_z/n_ref. В программе E,I и k_B в этих формулах выражены в согласованных единицах эВ и K.

Система для концентраций:

```math
v+x_{z+1}-x_z=\ln K_z^*,\quad z=0,\ldots,Z-1;\qquad
a_e=\sum_{z=1}^{Z}za_z;\qquad
\gamma a_e+\sum_{z=0}^{Z}a_z=B,\quad B=\frac{p}{k_BT_h n_{\rm ref}}.
```

Строки ионизации и заряда в линеаризации сохраняют вид. В строке давления коэффициент при новом v равен gamma·a_e, а правая часть равна B+gamma·a_e(v−1)+Σa_z(x_z−1). Эти коэффициенты пересчитываются на каждой итерации. Начальная оценка для нейтрала и однократного иона получается из a₁=a_e=u, a₀=u²/K₀*:

```math
u=\frac{2B}{1+\gamma+\sqrt{(1+\gamma)^2+4B/K_0^*}}.
```

Вычисления ведутся в логарифмах. При gamma=1 получается прежняя формула. В новом режиме статистические суммы и K_z* не зависят от состава, поэтому готовятся один раз для каждой точки прогонки. Исходные уравнения Саха, баланс заряда и двухтемпературный баланс давления проверяются перед признанием сходимости.

## Результаты

- `results/concentrations.csv`: все запрошенные точки, входные параметры, концентрации электронов и тяжёлых частиц, Γ, α, максимальная ΔI, итерации, ошибки и статус.
- `results/plots/*_group*.png`: отдельные группы концентраций по температуре, логарифмическая ось концентраций. Несошедшиеся точки показаны пропусками.
- `results/data_validation.json`: число прочитанных и исключённых строк каждого файла, причины, предупреждения.
- `results/run_metadata.json`: настройки, единицы, количество уровней, ограничения модели.

Выходные файлы перезаписываются при новом запуске в ту же папку. Для сохранения разных опытов укажи разные `output_dir`.

Обычный запуск `uv run main.py` использует `max_charge=4` из `config.py`. Сначала совместно вычисляются концентрации всех частиц; затем строятся четыре группы графиков. Выбор группы меняет только изображение, а CSV сохраняет все рассчитанные концентрации.

| Группа | Кривые | Пример имени PNG |
|---|---|---|
| 1 | Нейтралы, ионы +1, электроны | Xe_ideal_group1_neutral_ion1_e.png |
| 2 | Ионы +1, электроны, ионы +2 | Xe_ideal_group2_ion1_e_ion2.png |
| 3 | Ионы +2, ионы +3 | Xe_ideal_group3_ion2_ion3.png |
| 4 | Ионы +3, ионы +4 | Xe_ideal_group4_ion3_ion4.png |

При двух элементах и двух режимах получается 16 PNG. Каждая группа имеет свой масштаб вертикальной оси; цвета одной и той же частицы совпадают между графиками.

В `config.py` можно выбрать `plot_groups=(1, 3)` или включить дополнительный общий график через `plot_all_species=True`. Общие графики сохраняются как `Xe_ideal.png` и аналогичные файлы. Те же настройки доступны из командной строки:

```bash
uv run main.py --plot-groups 1 3
uv run main.py --plot-groups 1 2 3 4 --plot-all
```

Для упрощённого состава можно запустить `uv run main.py --max-charge 1`. Группы, требующие отсутствующего заряда, целиком пропускаются с сообщением и отметкой `skipped_plot_groups` в метаданных. Если не доступна ни одна выбранная группа и выключен общий график, программа сообщает об ошибке настроек. Ось концентраций логарифмическая, поэтому видны также очень малые концентрации старших ионов при низкой температуре.

Коды завершения: 0 — успешно, 1 — есть несошедшиеся точки, 2 — ошибка данных или настроек.

## Проверки

```bash
uv run python -m unittest discover -s tests -v
```

Для версии **0.3.0 прошли все 60 тестов**. В новом режиме `--fixed-gamma 1` сошлись все 436 точек для Xe и Cs в обоих моделях при Tₕ=3000–30000 K: концентрации полностью совпали с CSV прежней прогонки. При `--fixed-gamma 2` сошлись все 218 идеальных точек на той же сетке Tₕ; Tₑ изменялась от 6000 до 60000 K. Максимальные относительные ошибки давления и заряда, пересчитанные из CSV, — 9.13e-9 и 9.04e-9, максимальная логарифмическая ошибка Саха — 1.43e-14. Проверены подписи gamma и оси Tₕ, постоянство отношения температур на промежуточных шагах и отдельные папки для разных gamma. Примеры нового вывода находятся в `results_fixed_gamma_1` и `results_fixed_gamma_2`, численные итоги — в `verification.json`. Это проверка решения выбранной системы с зарядами до +4, а не экспериментальная проверка модели во всём температурном диапазоне.

Тесты проверяют NIST-подобный формат, единицы, дробные J и маркеры, согласованность спектра и заряда, номера строк в отчёте, матрицу по конечным разностям, аналитический двухсостоянийный случай, идеальный многозарядный случай по независимому скалярному решению, уравнение Γ и полный цикл CSV/PNG. Отдельная проверка сопоставляет каждую кривую всех четырёх групп со значениями соответствующих столбцов CSV и проверяет постоянство цветов. `test_supplied_nist.py` дополнительно проверяет все десять приложенных таблиц уровней и реальные пороги ионизации.

Основные численные тесты используют синтетические таблицы и не являются физическими данными Xe/Cs. Тесты `test_supplied_nist.py` относятся к включённому набору NIST CSV: при его замене контрольные количества уровней нужно пересмотреть. Совпадение результатов модели с независимыми физическими контрольными данными — отдельный следующий этап.

Для версии 0.2.0 выполнены запуски через `uv` с зависимостями из `uv.lock`; **прошли все 52 теста**. Новые проверки включают две температуры в матрице, независимое скалярное решение многозарядного идеального случая, аналитическое решение двухсостоянийной модели при Tₑ>Tₕ и Tₑ<Tₕ, адаптивную протяжку при фиксированной Tₕ, соответствие оси графиков столбцу gamma и отказ от неоговорённых неидеальных поправок.

На включённых CSV сошлись все **34 двухтемпературные точки**: Xe и Cs, p=100000 Па, Tₕ=4000 K, gamma=1–5 с шагом 0.25, max_charge=4. Созданы 10 PNG (четыре группы и общий график каждого элемента). Максимальная относительная ошибка давления, заново вычисленного по CSV, — 9.59e-9, баланса заряда — 9.93e-10. При gamma=1 максимальное относительное отличие концентраций от исходной программы — 3.48e-10.

Прежняя однотемпературная прогонка 3000–30000 K с шагом 250 K также выполнена для обоих элементов и обоих режимов: **436 точек, все сошлись**. Максимальное относительное отличие концентраций от программы из исходного архива — 1.84e-16. Дополнительно для Xe и Cs проверено восстановление прежнего состава при сохранении Tₑ=8000 K, изменении Tₕ до 4000 K и пересчёте давления. Численные итоги проверок сохранены в `verification.json`. Они проверяют реализацию выбранных уравнений, но не являются экспериментальной проверкой двухтемпературной модели.

## Файлы программы

- `config.py` — начальные параметры.
- `main.py`, `plasma/cli.py` — запуск.
- `plasma/data.py` — загрузка и проверка CSV.
- `plasma/model.py` — статистические суммы, поправки, уравнение Γ, матрица.
- `plasma/solver.py` — семинарские итерации и контроль шага.
- `plasma/runner.py` — три вида прогонки и продолжение.
- `plasma/output.py` — таблицы, отчёты и графики.
- `tests/` — воспроизводимые проверки.
