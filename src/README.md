# Расчёт состава плазмы Xe и Cs

Python-программа по семинарской схеме: линеаризация уравнений по логарифмам концентраций, решение линейной системы методом Гаусса/LU, отдельное половинное деление для параметра неидеальности Γ. При линеаризации коэффициенты и поправки фиксируются; при проверке пробного состава пересчитываются заново.

**Первая версия — однотемпературная: Tₑ = T.** Xe и Cs считаются отдельно. Энергия, транспорт и окончательное двухтемпературное замыкание относятся к следующему этапу. Набор связанных уровней фиксирован и не меняется из-за ΔI в ходе решения.

## Быстрый запуск

Требуются `uv` и Python 3.10 или новее. Из папки, где лежат `main.py` и `pyproject.toml`:

```bash
uv sync --locked
uv run main.py --validate-only
uv run main.py
```

Приложенные пользователем 12 исходных NIST CSV уже находятся в `input`, без изменений содержимого. Перед расчётом можно проверить отчёт `results/data_validation.json`. Файл `uv.lock` фиксирует версии зависимостей; `uv sync --locked` создаёт окружение `.venv`. Активировать его вручную при запуске через `uv run` не требуется.

Если ты самостоятельно меняешь зависимости в `pyproject.toml`, выполни `uv sync` без `--locked`, чтобы обновить `uv.lock`.

Команды для отдельного режима:

```bash
uv run main.py --element Xe --model ideal
uv run main.py --element Cs --model nonideal
uv run main.py --max-charge 4 --output-dir results_z4
```

Пути можно переопределить аргументами `--input-dir` и `--output-dir`. `--quiet` отключает промежуточную печать, но сохраняет файлы. Также доступна команда `uv run plasma-xe-cs` с теми же аргументами. Начальные физические параметры редактируются в `config.py`.

## Начальные настройки

Все параметры находятся в `config.py`, в объекте `SETTINGS`:

| Параметр | По умолчанию |
|---|---|
| Вещества | Xe, Cs |
| Режимы | ideal, nonideal |
| Давление | 100000 Па = 1 бар |
| Температура | 3000–10000 K |
| Шаг температуры | 250 K |
| Максимальный заряд | +4; на графиках нейтрал, ионы +1, +2, +3, +4 и электроны |
| Точность уравнений | 1e-8 |
| Точность Γ | 1e-12 |
| Предел итераций | 150 |
| Показ окон графиков | выключен, PNG сохраняются |

Конечная температура включается в сетку; последний интервал может быть короче заданного шага. По температуре применяется продолжение: используется предыдущий сошедшийся состав. При сбое допускаются промежуточные температуры, ограниченные параметрами `continuation_depth` и `minimum_temperature_step_k`.

## Входные файлы

Файлы уровней: `input/energy_levels/xe_1.csv` ... `xe_5.csv` и аналогично `cs_1.csv` ... `cs_5.csv`. **Суффикс 1 — нейтрал (заряд 0), суффикс 2 — заряд +1.** При максимальном заряде +1 нужны только первые два файла каждого элемента.

Пороги: `input/ionization_energies/xe.csv` и `cs.csv`. Нужна полная таблица ионизации, включая порог последнего учитываемого иона: он используется для отбора его связанных уровней. Например, для состава 0,+1 нужны пороги 0→+1 и +1→+2, хотя второй порог не входит в уравнение перехода внутри состава.

Поддерживается исходная выгрузка NIST CSV/Tab-delimited, в том числе текстовые обёртки `="..."`, разделённые `Prefix/Level/Suffix`, дробные J. Можно использовать нормализованные CSV:

```csv
energy_eV,J
```

или

```csv
energy_eV,g
```

Здесь `g` — статистический вес 2J+1, а не фактор Landé. Заголовки NIST `Level (eV)`, `Level (cm-1)`, `J`, `Configuration`, `Term` распознаются непосредственно. Нормализованная таблица порогов:

```csv
charge,ionization_energy_eV,uncertainty_eV
```

Вместо этих названий поддерживаются NIST `Ion Charge`, `Ionization Energy (eV)`, `El. Name`/`Element name`, `Sp. Name`/`Spectrum name`. Заряд при наличии только спектра или пустой ячейки заряда восстанавливается из обозначений Xe I, Xe II и т.д. Если указаны и спектр, и заряд, проверяется их согласованность; элемент также проверяется. Пустой последний столбец NIST не мешает чтению.

Единицы энергии читаются из заголовка; поддерживаются eV, cm^-1, Rydberg, Hartree, GHz. Если единицы отсутствуют, применяется **явная настройка** `default_energy_unit` и выводится предупреждение. Перед расчётом её нужно проверить. Внутри программы энергии выражены в эВ, температуры — K, давление — Па, физические концентрации — м^-3.

### Что делает проверка данных

- Требует основной уровень с энергией 0 и положительные статистические веса.
- Исключает строки Limit, отсутствующие/неоднозначные энергии и J, автоионизационные строки с соответствующим маркером.
- При `bound_levels_only=True` исключает уровни с энергией не ниже исходного порога. Это фиксированный набор; понижение порога не меняет его в данной версии.
- Перечисление J через запятую трактует как неразрешённые уровни с суммарной кратностью; альтернативы через `or` исключает и отражает в отчёте.
- Сохраняет число исключений и до трёх примеров каждой причины: исходные ячейки и номера строк CSV. Пропуски не заменяются нулями.
- Считает принятые энергии с квадратными/круглыми скобками в `estimated_rows`. Численное значение используется без скобок; число таких строк сохраняется в отчёте.
- Сообщает о точных повторах строк, но не объединяет уровни только по равенству энергии.
- При нехватке обязательного файла/основного уровня/порога прекращает расчёт с понятным сообщением.

Мало уровней или исключённые неопределённые строки могут существенно влиять на статистические суммы. Успех численного решателя не означает полноту атомных данных.

Для включённых CSV при `max_charge=4` принимается следующее число уровней:

| Элемент | Нейтрал | +1 | +2 | +3 | +4 |
|---|---:|---:|---:|---:|---:|
| Xe | 342 | 161 | 157 | 94 | 53 |
| Cs | 174 | 303 | 173 | 115 | 49 |

В частности, в `xe_1.csv` исключаются две строки `Limit` и 101 уровень с энергией не ниже первого порога ионизации. Это следствие настройки `bound_levels_only=True`, а не ошибка CSV. В `cs_1.csv` выше порога исключаются четыре уровня. Фильтр сравнивает энергии с исходным порогом; изменение статистических сумм из-за ΔI пока не моделируется.

## Формулы и численный метод

Используется масштаб n_ref = 10^24 м^-3 = 10^18 см^-3. Неизвестные — y=(v,x₀,...,x_Z), где aₑ=exp(v), a_z=exp(x_z), n=a·n_ref.

В `model.py` по физическим константам вычисляются коэффициенты листочка: A* ≈ 2.414683e-3, CΓ ≈ 5.863360e10, Cα ≈ 2.842511e-12. Давление нормируется как B=p/(k_BT n_ref), поэтому неоднозначная подпись «атм» с фотографии не используется.

Уравнения: v+x_(z+1)-x_z=ln(K_z*), aₑ=Σza_z, aₑ+Σa_z−α=B. В идеальном режиме Γ=α=ΔI=0. В неидеальном Γ находится половинным делением на доказанном интервале [0,Γ_D], затем вычисляются α и ΔI. При поиске Γ используется нормированная неизвестная q=Γ/Γ_D, что позволяет задавать точность независимо от малого значения самого Γ.

Система для новых логарифмов собирается напрямую, с замороженными поправками. В `np.linalg.solve` используется LU с выбором главного элемента — библиотечная реализация исключения Гаусса. Если полный шаг ухудшает ошибки исходных уравнений, он уменьшается. Начальное приближение получается аналитически для нейтрала и однократного иона; старшие состояния добавляются по логарифмической рекурсии Саха.

Успех принимается по выполнению ионизационных соотношений, относительному балансу заряда и давления и точности Γ. Малый шаг не используется вместо проверки уравнений. При несходимости сохраняется статус `failed`; пробные концентрации не выдаются за результат.

Alpha — поправка давления. Коэффициент уменьшения численного шага внутри решателя называется eta.

## Результаты

- `results/concentrations.csv`: все запрошенные точки, входные параметры, концентрации электронов и тяжёлых частиц, Γ, α, максимальная ΔI, итерации, ошибки и статус.
- `results/plots/Xe_ideal.png` и аналогичные PNG: концентрации по температуре, логарифмическая ось концентраций. Несошедшиеся точки показаны пропусками.
- `results/data_validation.json`: число прочитанных и исключённых строк каждого файла, причины, предупреждения.
- `results/run_metadata.json`: настройки, единицы, количество уровней, ограничения модели.

Выходные файлы перезаписываются при новом запуске в ту же папку. Для сохранения разных опытов укажи разные `output_dir`.

Обычный запуск `uv run main.py` использует `max_charge=4` из `config.py`: концентрации всех четырёх зарядов вычисляются совместно и выводятся на каждый график и в CSV. Для упрощённого состава можно запустить `uv run main.py --max-charge 1`. Ось концентраций логарифмическая, поэтому видны также очень малые концентрации старших ионов при низкой температуре.

Коды завершения: 0 — успешно, 1 — есть несошедшиеся точки, 2 — ошибка данных или настроек.

## Проверки

```bash
uv run python -m unittest discover -s tests -v
```

Тесты проверяют NIST-подобный формат, единицы, дробные J и маркеры, согласованность спектра и заряда, номера строк в отчёте, матрицу по конечным разностям, аналитический двухсостоянийный случай, идеальный многозарядный случай по независимому скалярному решению, уравнение Γ и полный цикл CSV/PNG. `test_supplied_nist.py` дополнительно проверяет все десять приложенных таблиц уровней и реальные пороги ионизации.

Основные численные тесты используют синтетические таблицы и не являются физическими данными Xe/Cs. Тесты `test_supplied_nist.py` относятся к включённому набору NIST CSV: при его замене контрольные количества уровней нужно пересмотреть. Совпадение результатов модели с независимыми физическими контрольными данными — отдельный следующий этап.

На включённых CSV выполнен запуск через `uv`: прошли 39 тестов, а также расчёты при p=100000 Па, T=3000–10000 K с шагом 250 K, отдельно для max_charge=1 и max_charge=4. В каждом расчёте сошлись все 116 точек (два элемента × два режима × 29 температур), ошибки уравнений ниже 1e-8, ошибка уравнения Γ ниже 1e-12.

## Файлы программы

- `config.py` — начальные параметры.
- `main.py`, `plasma/cli.py` — запуск.
- `plasma/data.py` — загрузка и проверка CSV.
- `plasma/model.py` — статистические суммы, поправки, уравнение Γ, матрица.
- `plasma/solver.py` — семинарские итерации и контроль шага.
- `plasma/runner.py` — температурная сетка и продолжение.
- `plasma/output.py` — таблицы, отчёты и графики.
- `tests/` — воспроизводимые проверки.
